# 方案 A 实验方案：CXL 内存延迟测量的系统性偏差

## 一、论文主张（一句话）

现有 CXL 内存延迟测量在两个维度上系统性地偏离真实工况——
**缓存复用**压低绝对值，**并发度恒为 1** 选错了工况——
据此得到的链路速率投资优先级是错的。

## 二、三个可辩护的贡献

**C1 偏差量化**：四类测量伪影，每类带剂量反应曲线和具体偏差幅度。

**C2 工况错配**：依赖指针追逐的 MLP 恒为 1，而真实服务的 MLP 在 8–32。
用 K 链交错仪器扫出延迟–并发度曲线，定位拐点，证明真实负载落在拐点之后。

**C3 自然实验**：同型号、同固件、同机器的两块设备，协商速率 16 vs 32 GT/s。
测出链路速率的真实边际价值，并给出与 C2 交互后的策略结论。

核心结论（预期）：**16 GT/s 在本地只慢 ~16%，一旦跨路就被 ~350 ns 的跳转代价
淹没到 ~5%。因此为降低尾延迟去买链路带宽是低优先级投入。**

## 三、实验矩阵

### E0 · 仪器（前置，1 天）

`multichase`：单线程内 K 条互不相干的依赖链交错遍历。

- `K` 精确等于 MLP，是自变量不是观测量（本机无 `l1d_pend_miss.pending` 事件，
  所以只能构造、无法测量——这反而更干净）
- 每条链覆盖 `--size-mb/K`，总工作集固定，保证六条路径可比
- 同时记录：逐次延迟、时间戳、实际完成访问数
- 校验：K=1 必须复现第 3 轮的冷访问数值（470.8 ns，±5%），否则仪器有问题

### E1 · 链路速率自然实验（C3，0.5 天）

补第 3 轮缺失的 n3-local 冷访问，并扩展到 K 扫描。

| 因素 | 水平 |
|---|---|
| 路径 | node2-local(16GT/s)、node2-cross、node3-local(32GT/s)、node3-cross |
| MLP | K = 1, 2, 4, 8, 16, 32 |
| 负载 | 空载、4 线程读 |

关键对比：**同 socket 内 16 vs 32 GT/s**（node2-local vs node3-local，都是 CPU0
发起、都是本地节点），这是唯一干净隔离链路速率的对照。

### E2 · 并发度拐点（C2，1 天）

K = 1…32 全扫，全部六条路径，空载。

产出：延迟–MLP 曲线。要回答：

1. 拐点在哪个 K？
2. 拐点是否随路径移动？（移动 = 共享资源竞争；不动 = 每核本地资源）
3. 饱和后延迟趋近什么值，与带宽的关系是否符合 `延迟 = 基础延迟 + 排队项`？

### E3 · 干扰域拆解（2×2，0.5 天）

第 3 轮的带载放大（本地 3.93×、跨路 1.32×）混了两个因素。拆开：

| | 负载打 node0 DRAM | 负载打 node2 CXL |
|---|---|---|
| 探针在 socket0（本地） | A | B |
| 探针在 socket1（跨路） | C | D |

A vs B = 同设备竞争的影响；A vs C = 同 socket CPU 竞争的影响。
这一格是回答审稿人"你凭什么说是干扰域不是 NUMA 距离"的关键。

### E4 · 伪影量化（C1，已有数据，补 0.5 天复核）

| 伪影 | 状态 | 需要的补充 |
|---|---|---|
| MLC `-r` 块内复用 | 已有剂量反应（58%→0.71%） | 无需 |
| `LLC-loads` 含页表遍历 | 已有反例（趋势完全反向） | 复现 2 次 |
| chase 环形复用 | 部分（46.1% vs 24.2% 未对齐） | **必须串行重测定论** |
| 并发度恒为 1 | E2 直接证明 | 无需 |

## 四、必须先解决的已知问题

1. **46.1% vs 24.2% 矛盾**（第 3 轮遗留）。两种测法在同一 128 MiB 环上差一倍。
   必须在写进论文前定论——否则 C1 里那条会被审稿人抓住。
   计划：串行重测，统一用 `pebs_probe` + 同一预热策略 + `ocr` 计数。
2. **E0 校验**。K=1 不能复现 470.8 ns 就停下改仪器，不要往下跑。

## 五、审稿人会问的三个问题（必须预备）

1. **"这和 Melody 的区别是什么？"**
   Melody 是性能刻画（265 负载、4 设备、5 平台）。本文是测量方法学：
   卖的不是"CXL 有多快"，是"已有的 CXL 延迟数字在什么条件下不可信"。
   必须明确写出"我们不主张新的性能数字，我们主张已有数字的误差结构"。

2. **"为什么只有一台机器？"**
   把主张绑定在机制上：四类伪影中，块内复用、环形复用、页表污染是**工具与
   访问模式的性质**，跨平台普适；只有绝对数值是机器相关的。
   同时 E1 的自然实验在同一机器内构造对照，不依赖跨机器比较。

3. **"MLP=1 真的会错吗？"**
   这是全文最脆的一环，必须靠 E2 的实测曲线和真实服务的 MLP 数据支撑。
   需要给出至少一个有出处的真实 MLP 范围（文献引用或自测）。

## 六、产出与投稿

- 目标：ICPE（ACM SIGMETRICS 旗下，专做性能工程）或 ICPADS/HPCC。
  被拒转 Cluster Computing / Journal of Systems Architecture。
- 时间：E0 1 天 + E1–E3 2 天 + E4 0.5 天 + 写作 3 周 ≈ 两个月投出。
- 数据规模：六条路径 × 6 个 MLP 水平 × 2 种负载 × 3 次重复 = 216 个单元，
  每单元 1M 样本，逐次记录，总量约 216 M 条。约 900 MB 原始数据。


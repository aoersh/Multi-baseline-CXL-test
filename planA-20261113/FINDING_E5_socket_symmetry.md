# E5：对称 DRAM 基线（2026-11-20）

## 目的

回应审稿意见 #4：论文比较 CPU0→node2（socket 0）与 CPU16→node3（socket 1），
这条对比里混了三个因素——链路速率、设备/插槽身份、socket/核侧不对称。
原有数据只有一半的对照，从未测过 CPU16→node1（socket 1 本地 DRAM）
和 CPU16→node0（socket 0 跨路 DRAM）。

本实验把 DRAM 上的 2×2 补全。DRAM 链路在两个 socket 上完全相同，
所以任何残余差异都是 socket/核侧效应。

## 方法

`multichase`，4 GiB 冷环，64 B 步长，K=1 与 K=8，每格 3 次重复，
`numactl --physcpubind` + `--membind`，落位经 `/proc/self/numa_maps` 校验。

| 单元 | CPU | 内存节点 | 路径性质 |
|---|---|---|---|
| cpu0-n0 | 0 | 0 | socket 0 本地 DRAM |
| cpu0-n1 | 0 | 1 | socket 0 → socket 1 跨路 |
| cpu16-n1 | 16 | 1 | socket 1 本地 DRAM |
| cpu16-n0 | 16 | 0 | socket 1 → socket 0 跨路 |

数据：`runs/e5-20261120-150555/results.csv`

## 结果

| 单元 | K=1 (ns) | K=8 (ns) |
|---|---:|---:|
| cpu0-n0（socket 0 本地） | 178.7 ± 1.0 | 38.4 ± 0.2 |
| cpu16-n1（socket 1 本地） | 177.9 ± 0.3 | 38.4 ± 0.1 |
| cpu0-n1（0 → 1 跨路） | 572.7 ± 1.0 | 109.9 ± 0.1 |
| cpu16-n0（1 → 0 跨路） | 581.7 ± 1.1 | 112.0 ± 1.6 |

### 两个 socket 的本地路径几乎完全相同

| | K=1 | K=8 |
|---|---:|---:|
| 差值 | **−0.8 ns（−0.4%）** | **0.0 ns（0.0%）** |

### 跨路方向也接近对称

| | K=1 | K=8 |
|---|---:|---:|
| 差值 | +9.0 ns（+1.6%） | +2.2 ns（+2.0%） |

## 结论

**socket/核侧不对称可以排除，至少对本地访问是这样。**

CXL 在 K=1 的差距是 79.7 ns。同一对 socket 上的本地 DRAM 差距只有 −0.8 ns，
即 **1.0%**。因此：

- socket 侧不对称最多解释 CXL 差距的 **1%**
- 其余 **99%** 归因于设备或链路

这否定了审稿意见 #4 中 (c) 这一项。先前我基于四格代数推导的
"socket 路径差约 30 ns / 占 37%" 是错的——那个推导隐含了"路径代价随所在
socket 翻转"的假设，实测数据两者都不符合。正确做法就是本实验的直接对照。

## 仍然未解决的

审稿意见 #4 的另外两个因素仍然纠缠在一起：

- **(a) 链路速率** 16 vs 32 GT/s
- **(b) 设备与插槽身份** —— 两块不同的物理设备、不同 root port、
  不同 retimer 个体

本实验只排除了 (c)。要拆开 (a) 和 (b)，需要以下之一：

1. **交换两块设备的插槽** —— 物理操作，会改变链路协商结果，
   破坏现有全部对照
2. **强制 mem1 降到 Gen4** —— 需要写 PCIe Link Control 2 的
   Target Link Speed 并重训练，需要 root 且有风险

两者都未执行。这是论文剩余的主要限制。

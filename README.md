# CXL Tail-Latency Measurement Study

测量工具与实验数据：CXL 内存延迟测量的方法论，以及一次链路训练降级的完整调查。

**完整研究过程见 [`RESEARCH_PATH.md`](RESEARCH_PATH.md)，论文初稿见
[`planA-20261113/PAPER_DRAFT.md`](planA-20261113/PAPER_DRAFT.md)。**

## 核心结论

**空载延迟评估会严重低估一条降级链路的代价，一个竞争线程就足以让它翻倍。**

同一台机器上两块同型号、同固件的 CXL 设备，协商速率分别是 16 GT/s 和 32 GT/s
（这是一次链路训练降级，不是配置）。本地访问、同一 CPU 发起的条件下：

| 负载线程 | 16 GT/s | 32 GT/s | 差距 |
|---:|---:|---:|---:|
| 0 | 89.5 ns | 75.5 ns | 18.5% |
| 1 | 115.8 ns | 83.6 ns | **38.6%** |
| 4 | 243.2 ns | 143.3 ns | 69.7% |
| 8 | 302.4 ns | 165.3 ns | **82.9%** |

"代价"有三种定义，相差 6 倍，论文 §4.2.1 全部报告：
相对于空载，差距比值放大 **4.5×**（8 线程）、绝对惩罚放大 **9.8×**、
延迟比放大 **1.54×**。早期草稿中的"4.5–6×"混用了两个不同探针配置的分母，已修正。

**已验证成立的两条**：静默降级确实存在（寄存器级证据）；空载评估低估且
一个竞争线程就翻倍。

**已降级的**：干扰域分解（node3 上不复现，0.7–1.5× 而非 6.4–8.0×）；
绝对带宽天花板（测量不可靠）；设备饱和度（无法排除）。

## 方法论警示

本项目的四轮实验里，每一个用过的仪器都先给出过一个看起来像硬件效应的假象。
这些已量化并写入各轮报告，值得单独列出：

1. **MLC `-r` 不是全缓冲区随机**——它在 `-D` 个 cache line 的块内随机，
   块内复用使 12% 的样本落在 0–31 周期。用 `-D` 扫描证实（58% → 0.71%，
   台阶正好落在 L2 容量 2 MiB）。
2. **`LLC-loads` 含页表遍历**——工作集越大 TLB miss 越多，而页表项常驻 L3，
   导致命中率随工作集**上升**，与真实趋势完全相反。须用 `ocr.demand_data_rd.*`。
3. **环形复用**——用 256 MiB 环反复遍历，L3 能装下 28%，绝对值偏低 10–13%。
   改为 4 GiB 环、单遍采样才得到真正的冷访问延迟。
4. **Little's law 误用**——整轮计时测的是 K 个访问中最晚完成的那个，
   "吞吐 × 平均延迟"天然低于 K。正确判据是零假设检验 E[max of K]。
   K≤8 时比值为 1.00–1.06×，并发是真的。
5. **带载实验的负载未匹配**——负载线程若与被测内存不在同一 socket，
   注入强度天然偏低，曾造成 150–240% 的虚假差距。
